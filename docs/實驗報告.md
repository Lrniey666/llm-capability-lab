## 2. 方法與架構

雲端走 Chat Completions HTTP（PyPI `openai` 用戶端）；本機 Ollama 走官方 `/api/chat`。換供應商等於換 `base_url` + `api_key` + `model`。

### 2.1 嘗試順序

```
groq / KEY → KEY2 → KEY3
  → gemini / KEY → KEY2 → KEY3
    → mistral / KEY → …
      → local / Qwen3.5-4B
```

雲端依延遲排：Groq 最快、Gemini 墊中、Mistral 額度大但約 1 req/s。本機永遠最後，opt-in（`.env` 填了 `LOCAL_BASE_URL` 才納入）。

當日預設模型：

| Provider | 模型 | 備註 |
|---|---|---|
| Groq | `openai/gpt-oss-20b` | 原 `llama-3.1-8b-instant` 已 404 |
| Gemini | `gemini-3.6-flash` | 原 `gemini-2.5-flash` 新帳號不可用 |
| Mistral | `ministral-3b-latest` | `mistral-small-latest` 免費層持續 429 |
| Local | `qwen3.5:4b` | Ollama `http://127.0.0.1:11434/v1`；預設 `think: false` |

### 2.2 錯誤怎麼切

| 錯誤 | 行為 |
|---|---|
| 429 / 5xx / timeout | 同一把依 `Retry-After` 重試；次數用完換下一把（換鑰匙不等待） |
| 401 / 403 | 這把無效，立刻換下一把 |
| 400 / 404 | 請求或模型有問題，跳過這家剩下的金鑰，換下一家 |
| 沒填的槽 | 自動略過 |

`check` / `bench` 固定用第一把，避免診斷時把備用額度打光。`ask` / `fallback` / `Router` / Discord 範例走完整輪替。

多用戶模擬條件：20 分鐘、每人冷卻 10 秒、思考平均 35 秒、seed=42。配額取當日實測：Groq TPM 8000、Gemini 5 RPM / 20 RPD、Mistral 1 req/s。本機假設 8 秒、無雲端配額、**不模擬 GPU 排隊**。

## 4. 分析

**同帳號多 key 不是備援。** 30 人時 Groq 1 key 成功率 48.5%，同專案 3 key 只有 49.4%，429 卻從 407 暴增到 2786。配額在組織／專案層，換鑰匙救不了 429。401 失效的單一把 key，備用鑰匙仍然有意義。

**真正拉開差距的是換供應商。** 15 人 Groq 獨力 88%，三家串起來約 98–99%。30 人三家約 83–95%，視重試次數而定。Gemini 日額約 20 則，很快交棒；Mistral 在高負載時扛走數百則，但是 1 req/s。

**重試要省著用。** 3×3 共桶加 `retries=1`，30 人成功率 95.2%，浪費 5704 次 429，等於拿配額換一點成功率。走到本機之前若先把雲端重試打滿，使用者會先等一輪 timeout。

**本機保底補的是可用性，不是速度。** 沒有 9 個獨立 Groq 帳號時，加上 Qwen 才能在模擬裡把 15 / 30 人打到 100%。代價是 p95 從約 1 秒升到 5–10 秒；30 人時本機要接 91–137 則。模擬假設每次本地 8 秒且無排隊，CPU 實機會更慢。5 人 Groq 就夠，本機此時沒差。

**任務要分通道，不要把所有請求丟進同一條品質假設。**

| 通道 | 現況較適合 |
|---|---|
| 給人看的短繁中 | Groq（快）→ Gemini → Mistral → 本機 Qwen |
| 給程式看的 JSON | 雲端目前只有 Mistral 穩；Groq / Gemini 的 `json_object` 當日失敗 |
| 菜單圖 | 預設 gpt-oss 不能接；`qwen/qwen3.8-27b` 能接（2026-09-18 補測）。Gemini 常截斷或漏思考文字；Mistral JSON 合法但 OCR 弱 |

前台用 Qwen3.5-4B、結構化另派 Phi-4-mini 的構想，方向對，但當日沒有兩顆本機模型的實測。Phi 不能直接看圖；同一輪又回覆又抽 JSON 還會在 8GB 卡上卸載切換。在本機 RAM 只夠一顆時，先駐 Qwen 做聊天／視覺，入庫 JSON 仍優先 Mistral。

## 5. 結論與建議

1. **免費層可以當 Discord 前台，前提是 Router 跨供應商，而不是同家多 key。** 預設順序 groq → gemini → mistral → local 合理。
2. **模型 ID 當組態，不當常數。** 寫死幾個月就 404。上線前跑 `python -m llmclab models`。
3. **Groq 當第一棒，盯 TPM 不是 RPD。** 長 system prompt 要開 prompt caching。`check` 短 `max_tokens` 對推理模型會得到空字串，不代表金鑰壞了。
4. **Gemini 不適合當唯一後備。** 日額約 20，多用戶很快見底；當日 JSON 與視覺 check 也不穩。
5. **Mistral 適合 JSON 與低併發批次，不適合高併發前台。** 結構化任務應單獨排，不要跟聊天搶同一條重試預算。
6. **本機 Qwen3.5-4B 值得留在架構裡，但要 opt-in、fail-fast 429、關 think。** 5 人用不到；15 人以上才看得出價值。啟用前先 `ollama pull qwen3.5:4b` 並填 `LOCAL_BASE_URL`，再用 `check -p local` 補實機數字。
7. **生產建議：** Discord 用 `retries_per_key=0` 或很小的 `max_attempts_per_provider`，讓 429 快點換下一家／本機，不要在同專案 KEY2 上空轉。每人冷卻 10 秒保留。回覆標 `via {provider}`，讓使用者知道何時已降級到本機。

## 6. 限制與後續

當日沒有量到：

- 真 429 後同一把的 `Retry-After` 退避（離線測試有覆蓋邏輯，實機避免把剩餘 TPM 打光故未刻意打滿）
- 本機 Qwen 的 TTFT、繁中品質、JSON、視覺
- 本機併發排隊（模擬把 local 當成無限 8 秒桶）
- Phi-4-mini 做 schema worker 的合法 JSON 比例
- 菜單圖的人工對答案（Mistral 可解析 ≠ 品名正確）

建議下一輪：

1. 啟用 Ollama 後跑 `check -p local`、`ask local`、菜單轉 JSON 的 local 欄。
2. 模擬加上本機單飛佇列，看 30 人時 p95 真實會爛到什麼程度。
3. 結構化通道獨立：雲端 Mistral 優先，本機用 grammar／`response_format`，不要跟聊天共用 sampling。
4. 若 RAM 允許，再比較 Qwen3.5-4B 與 Phi-4-mini 在「已有文字 → 固定欄位」上的可解析率。

### 4. 分析

**iAI 適合作第四雲端，不適合作第一棒。** `Furen-std`、`gemma-4-31b` 在簡易套件上與 Groq 同分、延遲約 0.4 s，比 Gemini 的 3 s 快一個數量級。Router 仍應 Groq 先打：免費、更快（0.8 s 且 TPM 內體感最好），把 iAI 留給 Groq TPM 與 Gemini 日額用完之後，避免校內額度被 Discord 閒聊打光。

**預設模型不要用 Nkust。** 它邏輯題會做，但對話拒答、又愛把 token 留在思考。規格書範例是 `Furen-large`；若在意「給人看的字不要洩 CoT」，今日資料裡 **Furen-std 比 Furen-large 乾淨**，延遲也穩。建議把聊天預設改成 `Furen-std` 或維持 `Furen-large` 但過濾／關 think（端點若支援）。

**分數 8/8 可能是假通過。** `has_cjk` 會把漏出來的英文思考裡的中文身分句算進去。對照報告必須抽看 `text`，不能只看合計。這也解釋為什麼 Furen-large 自我介紹「通過」卻不能直接丟給使用者。

**本機保底的假設要修正。** 昨天模擬用 8 s；今天平均 0.38 s，15 人情境裡那 6 則 local 接手幾乎不會拖到 5 s p95。30 人 137 則仍可能排隊，但單飛延遲不再是主因。品質上限仍在：倒排與雞牛兩題與 Mistral 3B 同級失敗。

**iAI 不是單一模型。** 同一把 key 底下混著 LLM、ASR、TTS、Embedding、Rerank、繪圖。`--iai-all` 的價值是把「拿錯端點」變成可重複實驗，而不是期待 Pic-small 通過乘法。

---

### 5. 結論與建議

1. **Router 順序維持 groq → gemini → mistral → iai → local。** iAI 已驗證可當跨供應商的下一棒。
2. **iAI 聊天用 `Furen-std` 或 `gemma-4-31b`；不要預設 `Nkust`、不要前台用 `Furen-max`。** coder / 120b 分數同樣滿，但較慢、較貴，留給需要時再 `IAI_MODEL` 覆寫。
3. **對外回覆不要直接信任 iAI 的「自我介紹」。** 校方身分句會蓋過使用者格式要求；產品 system prompt 要寫明「不要提學校」並用 deep 套件回歸。
4. **本機 Qwen3.5-4B 可以啟用。** 延遲已證明不是瓶頸；當 Groq／Gemini／Mistral／iAI 全滿時，6/8 的繁中短答比 `AllProvidersFailed` 好。倒排與應用算術不要指望它。
5. **對照流程固定兩段：** 先 `compare` 看預設四家，再 `compare -p iai local --iai-all` 掃校內目錄。第一輪 Groq 全空就先查 reasoning，不要重簽金鑰。
6. **價目表不能當可用清單。** `nvidia-ultra-550b` 今日 400。上線前仍以 `python -m llmclab models -p iai` 為準。

---
